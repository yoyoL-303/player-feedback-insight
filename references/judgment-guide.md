# 真实痛点 vs 伪需求 / 噪音 判断指南

## 真实痛点特征
- 多个玩家用不同表达描述同一问题
- 能明确指出「在什么场景下发生」
- 影响核心体验（卡关、流失、付费意愿下降）
- 玩家提出的往往是「症状」，背后可能有更深层原因
- 有可验证的影响面（影响某类玩家、某阶段、某系统）

## 伪需求 / 噪音特征
- 个人极端偏好（「我就是不喜欢这种画风」）
- 把愿望包装成问题（「希望加XX功能」但没有说明当前痛点）
- 情绪宣泄为主，缺乏具体场景
- 与当前版本目标明显冲突，且影响面极小
- 把个别bug或偶发问题上升为系统性问题

## 判断时的实用问题
1. 这个问题如果不解决，玩家会不会因此离开或大幅降低投入？
2. 有多少玩家在不同时间、不同渠道重复提到类似点？
3. 玩家描述的是「我遇到了什么障碍」，还是「我希望游戏变成我想要的样子」？
4. 这个反馈是否可能只是更深层问题的表面症状？

## 处理原则
- 高频率 + 高影响 → 优先处理
- 高频率 + 低影响 → 可记录，降低优先级
- 低频率 + 高影响 → 需要额外数据验证后再决定
- 低频率 + 低影响 → 通常归为噪音或个人偏好
